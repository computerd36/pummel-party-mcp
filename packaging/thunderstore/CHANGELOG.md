# Changelog

## 0.8.0 (unreleased)

- Mod settings tools: `list_mod_settings`, `get_mod_settings`, `set_mod_settings` (minigame/board details, minigame and player settings, music, lighting and screen effects with presets and custom values, board size and camera; clamps and conditions as the editor applies them; not undoable) and `capture_preview_image` (creates a screenshot texture in the sandbox mod and assigns it as preview image). Capability `settings`.
- `usage_guide` has topics; the server instructions are short.
- Asset tools (capability `assets`, config section `[Assets]`): `import_asset` (copies a local `.png .jpg .jpeg .obj .wav .mp3 .ogg` into the sandbox mod; the source is only read; never overwrites; size limits `MaxImportFileMB` 50 and `MaxModAssetsMB` 500), `set_import_settings`, `create_material`, `set_material`, `remove_asset` (only the mod's own custom assets; refused while referenced unless `force`), `get_asset` (with references) and `list_asset_rules`; `list_assets` gains `location`. This replaces the earlier rule that the plugin never imports or removes assets. Imports, material changes and removals write or delete files immediately and are not undoable.

- Prefab tools (capability `prefabs`): `create_prefab` (empty, or a copy of a scene object; refuses subtrees with Prefab Instance / Board Space components or object references; never reuses a name or overwrites a file), `open_prefab` and `close_prefab` (enter/leave the prefab edit context like the UI; closing saves the prefab and refreshes its instances). `remove_asset` also removes the mod's own prefabs; `get_asset` shows a prefab's object tree and scene instances. Prefab files are written immediately and are not undoable.
- `.pfab` write protection: a prefab the game fails to write completely makes the whole mod unloadable, so create, close and every prefab in `save_mod` are dry-run in memory first, verified afterwards (header, length) and restored from a copy taken before the write if bad (a new prefab's files are removed). A prefab that cannot be serialised now refuses `save_mod` before anything is written.

- Playtest-test fixes: the Change Health note is corrected (with Use Health off a value of 0 does nothing, whatever the operation; a non-zero value whose result is 0 or less kills; Kill/Destroy (type Kill) kills a player target without this arithmetic, a non-player target is deactivated). `add_action` and `set_action` return a warning when a target action has no target and will execute on nothing (the playtest feed still logs `action_executed`); `list_action_types` rows for Play Sound, Change Health and Kill carry a `note`. `duplicate_object` returns a top-level `guid` as `create_object` does. `create_material` refusals for an unknown shader list the valid names and the reply shows `shaderAsset` next to `shader`. `usage_guide` gains notes on shared spawns, LastManStanding points, built-in meshes and known harmless log lines.

- `usage_guide` gains notes from an obstacle-course build: falling never kills (catch zones), which spawns round start and respawn use, the checkpoint pattern (Position / Match Transform, Wait, invisible walls), `OneUsePerPlayer` is not reset per round, Set Placement points and ranking by total score, AI players never jump from the ground, music clips among the built-in sounds, the audio source pool warnings, local transforms in `create_object`, round layouts (RoundEnd / Set Active chain), players do not block each other, built-in prop search, the harmless `ArgumentOutOfRangeException` log line at a playtest start and invisible walls.

- `screenshot` takes an optional `camera` ({position, lookAt}, {position, rotation: {x pitch, y yaw}} or {focus: guid, rotation?}) that moves the Mod Editor's scene-view camera first (edit mode with a mod open); it is a view change only (no write guard, nothing in the mod changes, no undo step) and the reply carries the applied `camera`. `get_playtest_state` gains `audio` (music and ambience source with clip, volume, playing, time and length, the number of active pooled sources, and the player's master/music/effects volume). `list_assets` AudioClip rows carry `lengthSeconds` for loaded clips. `usage_guide` gains PUNCH KNOCKBACK (Can Punch, the On Weapon Hit trigger and a Change Player Velocity recipe) and SCREENSHOT CAMERA.

- Phase 4 review fixes: links (junctions, symlinks, mount points, hard links) inside a sandbox mod are never written or deleted through (new error `LINK_REFUSED`; `list_assets`/`get_asset` show `linked`); `start_playtest` protects the prefab files of its save like `save_mod`; the reference scan also covers the player-settings triggers, an Item mod's prefabs and icon and the Workshop thumbnail; import checks run on the copy inside the mod (staged as `.mcp-import`), audio is capped by duration (`[Assets] MaxAudioSeconds`, `MaxCompressedAudioMB`) and OBJ face lines are capped; an import interrupted by a crash is quarantined at the next start; `create_prefab` refuses an incomplete reference scan; failed restores keep their safety copy in `McpRecovery`; partial renames are detected; longer commit budgets (`import_asset` limit 120 s); `set_import_settings`, `set_material` and `close_prefab` are marked destructive.

## 0.7.0

- Game-version gate: write tools are refused with `GAME_VERSION_UNTESTED` on a game version the plugin was not tested with, until `[Safety] AcceptedGameVersion` equals the running version.
- New read tool `self_test`: checks that every game member the plugin needs still resolves, that the Workshop publish block is complete, and the inspector audit.
- `set_property` follows what each component's inspector can really produce (never-drawn properties, conditional properties, omitted choices are refused).
- `ModLight.spotAngle` is clamped to 1..179, the range the editor stores (200 becomes 179).
- First packaged build. Sandbox mods are named `MCP_...`.
